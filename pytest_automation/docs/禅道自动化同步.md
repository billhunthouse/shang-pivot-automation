# pytest 自动化结果同步禅道

> 目标：pytest 跑完后，自动把本次运行写入禅道，形成可追溯的测试套件、用例执行状态和失败 Bug。

## 1. 需求拆解

| 需求 | 实现 |
|---|---|
| 运行结束后自动同步 | `conftest.py` 的 `pytest_sessionfinish` 调用 `core/zentao_sync.py` |
| 包含运行状态和结果 | 每个 pytest 结果写入禅道用例的 `lastRunResult`：`pass/fail/n/a` |
| 失败自动创建 Bug | `ZenTaoApi.create_bug()`，标题带稳定用例编号 |
| 提交详细记录 | Bug `steps` 写入 run_id、nodeid、失败阶段、longrepr、耗时 |
| 提交截图和附件 | Bug 上传 UI 失败截图、Playwright trace、失败文本 |
| 测试用例套件 | 每次运行创建 `自动化回归-<env>-<run_id>` 测试套件，并关联本次用例 |
| 用例执行状态 | 通过禅道 `/testcases/{id}/results` 写入用例结果 |

## 2. 数据流

```text
pytest
  │
  ├─ pytest_runtest_makereport
  │    ├─ 记录 outcome / duration / longrepr
  │    └─ UI 失败截图 + Playwright trace
  │
  └─ pytest_sessionfinish
       │
       ├─ 读取 results / test_cases.json
       ├─ 创建禅道测试套件
       ├─ 创建/复用禅道测试用例（含 1 个自动化步骤）
       ├─ 写入用例执行结果
       ├─ 失败用例创建 Bug + 上传附件
       └─ 通过内部 UI 接口把用例关联进测试套件
```

## 3. 代码落点

| 文件 | 作用 |
|---|---|
| `core/zentao_sync.py` | 同步主逻辑：REST 客户端、UI 登录、套件关联、Bug 创建 |
| `conftest.py` | 在 `pytest_sessionfinish` 中调用同步，不改变 pytest 退出码 |
| `test_cases.json` | 稳定用例编号、标题、优先级、marker 来源 |
| `artifacts/zentao_case_map.json` | pytest nodeid → 禅道 case_id 的本地映射 |
| `artifacts/zentao_sync.json` | 本次同步报告：套件/用例/Bug/错误 |

## 4. 禅道 API 调研结论

实测 ZenTao 22.6：

| 操作 | 方法与路径 | 说明 |
|---|---|---|
| 登录 | `POST /api.php/v1/tokens` | 返回 Token |
| 查产品 | `GET /api.php/v1/products` | 拿 `product_id` |
| 建测试套件 | `POST /api.php/v1/products/{id}/testsuites` | 只创建套件 |
| 建测试用例 | `POST /api.php/v1/products/{id}/testcases` | JSON，步骤用 `steps[]` |
| 写用例结果 | `POST /api.php/v1/testcases/{id}/results` | 关键：不是 `/testresults/{id}` |
| 建 Bug | `POST /api.php/v1/products/{id}/bugs` | multipart 附件字段用 `files[]` |
| 套件关联用例 | `POST /zentao/index.php?m=testsuite&f=linkCase&suiteID={id}` | REST v1 没有 linkCase 路由，走内部 UI 接口 |

两个关键实测结论：

1. **`/testcases/{id}/results` 才是执行结果接口**；`/testresults/{id}` 会返回 `not found`。
2. **Bug 多附件必须使用 `files[]` 字段**；使用 `files` 只会保留最后一个附件。

## 5. 启用方式

```bash
cd pytest_automation

TEST_ENV=dev \
ADMIN_PASSWORD='Admin@123' \
ZENTAO_SYNC_ENABLED=1 \
ZENTAO_SYNC_MARKERS=smoke \
ZENTAO_BASE_URL=http://49.233.135.247:60084 \
ZENTAO_ACCOUNT=admin \
ZENTAO_PASSWORD_FILE=$HOME/.zcode/secrets/zentao-admin-password \
.venv/bin/python -m pytest -m smoke -q
```

常用变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `ZENTAO_SYNC_ENABLED` | `0` | 打开同步 |
| `ZENTAO_BASE_URL` | 空 | 禅道根地址 |
| `ZENTAO_ACCOUNT` | `admin` | 禅道账号 |
| `ZENTAO_PASSWORD_FILE` | 空 | 密码文件，推荐 600 权限 |
| `ZENTAO_PRODUCT_ID` | `1` | 产品 ID |
| `ZENTAO_PROJECT_ID` | `1` | Bug 关联项目 ID |
| `ZENTAO_SUITE_NAME` | `自动化回归` | 套件名前缀 |
| `ZENTAO_SYNC_MARKERS` | `smoke` | `smoke` / `all` / 逗号分隔 marker |
| `ZENTAO_SYNC_BUG` | `1` | 失败是否建 Bug |
| `ZENTAO_SYNC_ATTACHMENTS` | `1` | 是否上传附件 |

> 默认只同步 smoke，避免全量 845 条用例第一次就全部写入禅道。  
> 全量同步：`ZENTAO_SYNC_MARKERS=all`。

## 6. 实际验证

### 6.1 全部通过的 smoke 同步

执行：

```text
15 passed, 830 deselected in 30.05s
```

同步报告：

```json
{
  "suite": {
    "id": 5,
    "name": "自动化回归-dev-20261104-191120"
  },
  "cases": [
    {"stable_id": "API-AUTH-001", "case_id": 29, "outcome": "passed"},
    {"stable_id": "UI-BROWSE-001", "case_id": 40, "outcome": "passed"}
  ],
  "bugs": [],
  "errors": []
}
```

禅道测试套件中已验证 15 条用例全部关联，用例 `lastRunResult` 为 `pass`。

### 6.2 失败用例同步

临时构造一个 UI 失败用例验证：

```text
1 failed, 1 passed
```

验证结果：

- 创建测试套件成功；
- 失败用例执行结果为 `fail`；
- 自动创建 Bug；
- Bug 附件包含：
  - `*.png` 失败截图
  - `trace.zip` Playwright trace
  - `*.txt` 失败详情
- 验证后已清理临时套件、用例和 Bug，避免污染禅道。

### 6.3 Bug 标题与内容

标题格式：

```text
[自动化失败][UI-BROWSE-001] 商城首页加载商品
```

Bug `steps` 包含：

```text
运行 ID：20261104-191120
pytest 用例：tests/ui/test_mall_browse.py::...
执行状态：failed
失败阶段：call
耗时：30.1s

失败信息：
...
```

## 7. 已知限制

1. **套件关联走内部 UI 接口**：REST v1 没有 `linkCase`，所以 `ZenTaoWeb` 用账号密码登录 `/zentao/` 后调用 `testsuite/linkCase`；账号必须对产品有编辑权限。
2. **默认只同步 smoke**：全量 845 条会创建大量禅道用例，首次接入建议先用 smoke 验证流程。
3. **用例复用依赖标题**：首次按 `[自动化] <稳定编号> <标题>` 查找；找不到才创建。修改用例标题会产生新用例，修改稳定编号也会。
4. **Bug 不在跨轮次去重**：每轮失败都会新建 Bug；如果要合并同一问题，后续可加指纹字段（如 `nodeid + error hash`）。
5. **附件依赖本地产物**：UI 截图和 trace 由 `pytest_runtest_makereport` 生成；如果没有跑 UI 或禁用附件，只上传失败文本。

## 8. 排障

| 现象 | 检查 |
|---|---|
| `artifacts/zentao_sync.json` 为空/不存在 | `ZENTAO_SYNC_ENABLED=1` 是否设置 |
| `没有匹配 ZENTAO_SYNC_MARKERS` | 当前运行的 marker 与 `ZENTAO_SYNC_MARKERS` 是否匹配 |
| 套件关联失败 | `ZENTAO_ACCOUNT` 是否有产品权限；看 `errors` 字段 |
| Bug 没有截图 | UI 用例是否真的失败并生成 `artifacts/ui/failures/*.png` |
| 测试结果没变 | 检查是否请求了 `/testcases/{id}/results`，不是 `/testresults/{id}` |
| 多附件只保留一个 | 检查 multipart 字段是否使用 `files[]` |

## 9. 一句话总结

**pytest 负责产出事实（结果、失败堆栈、截图、trace），禅道负责沉淀资产（套件、用例状态、Bug、附件）；同步层只做搬运和映射，失败不能反过来影响测试结论。**
