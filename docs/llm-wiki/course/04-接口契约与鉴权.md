# 接口契约与鉴权：137 个端点怎么读

## 本节目标

- 从页面源码找到真实接口；
- 读懂统一响应结构和业务码；
- 区分公开、会员、管理员三类鉴权；
- 避免雪花 ID 精度坑。

## 1. 接口清单的构成

`data/apis.json` 共 137 个端点，字段包括：

```json
{
  "method": "POST",
  "path": "/api/reviews",
  "summary": "发表评价",
  "auth": "会员 token",
  "controller": "StorefrontController#createReview",
  "service": "-",
  "tables": []
}
```

按 tag 分组后，主要域有：

| 域 | 代表接口 |
|---|---|
| C 端商城 | `/api/products`、`/api/cart`、`/api/orders`、`/api/payment/sandbox` |
| C 端文件 | `/api/files/upload`、`/api/files/view` |
| 管理端商品 | `/admin/products`、`/admin/categories`、`/admin/stocks` |
| 管理端交易 | `/admin/orders`、`/admin/after-sales`、`/admin/reviews` |
| 身份权限 | `/admin/auth/login`、`/admin/users`、`/admin/roles` |
| AI 助手 | `/api/customer-service/chat` |

## 2. 从页面找接口

以商品详情为例：

```text
ProductView.vue
→ import { fetchProductDetail } from '@/api/catalog'
→ fetchProductDetail(id)
→ GET /api/products/{spuId}
```

再看评价提交：

```text
OrderDetailView.vue
→ import { createReview } from '@/api/order'
→ POST /api/reviews
```

> 追溯矩阵可能漏掉间接调用，**页面源码里的 import 才是第一手证据**。

## 3. 统一响应

后端统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

常见业务码：

| code | 含义 |
|---:|---|
| 0 | 成功 |
| 40000 | 参数/业务校验失败 |
| 40100 | 未登录或 token 失效 |
| 40300 | 无权限 |
| 40400 | 资源不存在 |
| 50000 | 服务端异常 |

注意：HTTP 状态可能是 200，但业务 `code` 是 40400。测试断言必须同时看 HTTP 和业务码。

## 4. 三类鉴权

| 类型 | 例子 | 规则 |
|---|---|---|
| 公开 | `GET /api/products*`、`GET /api/home`、`POST /api/customer-service/chat` | 白名单 |
| 会员 | `/api/cart`、`/api/orders`、`POST /api/reviews` | C 端 token |
| 管理员 | `/admin/**` | 管理端 token |

关键事实：

- 管理端与 C 端 token **不通用**；
- 后端 `/admin/**` 目前主要认证，细粒度 RBAC 主要影响前端菜单/按钮；
- 公开接口也要校验资源可见性，例如商品必须 `ON` 且未删除。

## 5. 雪花 ID 契约

后端把 `Long` 序列化为字符串：

```json
{ "id": "2120852188811464706" }
```

前端必须：

```ts
type Row = { id: string }
id: String(o.id)
```

禁止：

```ts
Number(o.id)      // 精度丢失
parseInt(o.id)    // 精度丢失
+o.id             // 精度丢失
```

真实事故：商家端发货请求把 `...4706` 变成 `...4700`，后端返回“订单不存在”。详见 L10。

## 6. 分页契约

常见参数：

```text
page=1&size=10
```

响应：

```json
{
  "total": 42,
  "records": []
}
```

测试要覆盖：

- 第一页、最后一页、超出页码；
- `size=0`、负数、超大值；
- 空结果；
- 排序稳定性。

## 7. 接口测试的最小断言集

```text
1. HTTP 状态码
2. 业务 code / message
3. 关键字段存在与类型
4. ID 是字符串且未被截断
5. 数据库副作用（库存、状态、流水）
6. 鉴权：无 token / 错 token / 过期 token
```
