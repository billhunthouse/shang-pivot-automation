# 新需求影响分析实战：评价商家回复

## 本节目标

- 把一条新需求拆成五层影响；
- 识别复用、修改、新增；
- 输出可执行的测试范围；
- 复盘哪些判断被代码推翻。

## 1. 需求输入

```text
商家可以在管理端回复商品评价；
回复在 C 端商品详情页展示；
回复 1–500 字；
回复不改变评价星级、内容、可见性。
```

## 2. 五层影响分析

### 需求层

- 新增 `EXT-REVIEW-REPLY-001`；
- 关联 `V2-FR-015`（发表评价）、`V2-FR-025`（评价管理）。

### 页面层

| 页面 | 改动 |
|---|---|
| `page:admin:/reviews` | 新增“商家回复”列、回复按钮、弹窗 |
| `page:mall:/product/:spuId` | 评价卡片展示商家回复 |

### 接口层

| 接口 | 复用/新增 |
|---|---|
| `GET /admin/reviews` | 修改：返回 `merchantReply`、`repliedAt` |
| `PUT /admin/reviews/{id}/reply` | 新增 |
| `GET /api/products/{spuId}` | 复用：`reviewsPreview` 增加字段 |

### 代码层

| 文件 | 改动 |
|---|---|
| `Review.java` | 新增 `merchantReply`、`repliedAt` |
| `ReviewAdminService.reply` | 新增：校验、写库 |
| `AdminOpsController` | 新增 `PUT /admin/reviews/{id}/reply` |
| `shang-admin-web/src/api/reviews.ts` | 新增 `replyReview` |
| `ReviewsView.vue` | 回复交互 |
| `ProductView.vue` | 展示回复 |

### 数据层

```sql
ALTER TABLE commerce.review
  ADD COLUMN merchant_reply TEXT,
  ADD COLUMN replied_at TIMESTAMPTZ;
```

## 3. 风险清单

| 风险 | 说明 |
|---|---|
| 空回复 | 前端/后端都要拦 |
| 超长 | 500 字边界，中文/emoji 口径 |
| 覆盖 | 重复回复是覆盖还是追加？本期覆盖 |
| 隐藏评价 | C 端只展示 `VISIBLE` 的回复 |
| XSS | 回复按文本渲染，不能插 HTML |
| 并发 | 两个管理员同时回复，后写覆盖 |
| 审计 | 是否记录操作日志和操作人 |

## 4. 测试设计

### API（7 条）

1. 回复成功 + C 端可见；
2. 重复回复覆盖；
3. 空回复 400；
4. 501 字 400；
5. 评价不存在 404；
6. 隐藏评价不在 C 端展示；
7. 无 token 401。

### UI（1 条）

```text
管理员登录 → 评价管理 → 找到评价 → 回复 → 保存
→ 打开商城商品详情 → 看到商家回复
```

## 5. 实现后的验证

```text
8 passed（API 7 + UI 1）
Allure 100%
```

关键回查：

- 管理端列表返回新字段；
- C 端 `reviewsPreview` 返回新字段；
- 隐藏评价的回复不公开；
- 评价星级/内容/状态未变。

## 6. 复盘：哪些判断被推翻

| 初始判断 | 实际 |
|---|---|
| 只改管理端 | C 端商品详情也要改 |
| 追溯矩阵已列全接口 | 漏了 `POST /api/reviews` |
| 保存成功就完成 | 必须跨端验证 C 端展示 |
| 种子评价可直接复用 | 重复执行会覆盖，需要专用 fixture |
