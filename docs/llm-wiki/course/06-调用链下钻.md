# 调用链下钻：Controller → Service → 表

## 本节目标

- 从接口路径找到 Controller 方法；
- 从 Controller 找到 Service 和 Mapper；
- 识别事务边界、锁、幂等和副作用；
- 用调用链设计集成测试。

## 1. 下钻方法

```text
接口路径
→ Controller 类 + 方法
→ Service 方法
→ Mapper / SQL
→ 表与字段
→ 事务/锁/事件
```

证据优先级：源码 > `call-graph.json` > `05-调用链路.md` > wiki 摘要。

## 2. 链路一：首页（N+1 风险）

```text
GET /api/home
→ StorefrontController.home
→ CatalogReadService.home
→ SiteBrandService / HomeSlotService
→ commerce.site_brand / home_slot / home_slot_item
→ 推荐流 toCard × N
→ commerce.spu / commerce.sku（每个 SPU 一次查询）
```

测试关注：

- 首页响应时间随推荐位数量增长；
- 运营位为空、商品下架、SKU 缺失时的降级；
- 缓存是否命中。

## 3. 链路二：商品详情

```text
GET /api/products/{spuId}
→ CatalogReadService.detail
→ commerce.spu + commerce.sku
→ available(skuId) → commerce.stock（每个 SKU 一次）
→ commerce.review（最近 5 条 VISIBLE）
```

测试关注：

- 下架/删除商品返回 404；
- 多 SKU 库存分别正确；
- 评价只返回 VISIBLE，最多 5 条；
- 评价为空时前端区块不渲染（产品体验问题）。

## 4. 链路三：提交订单（核心事务）

```text
POST /api/orders
→ StorefrontController.submit
→ OrderSubmitService.submit
→ identity.customer（NORMAL）
→ commerce.address（归属校验）
→ commerce.sku / spu（上架/可售）
→ commerce.stock（SELECT ... FOR UPDATE）
→ commerce.order + order_item（快照）
→ commerce.stock_log（LOCK）
→ commerce.cart_item（删除选中项）
```

测试关注：

- `idempotentKey` 重复提交；
- 库存不足、地址不存在、SKU 下架；
- 任一行失败整单回滚；
- 订单号唯一索引冲突；
- 购物车项是否删除。

## 5. 链路四：后台发货

```text
POST /admin/orders/{id}/ship
→ OrderService.ship
→ commerce.order（PENDING_SHIP）
→ commerce.shipment（SHIPPED + traces）
→ commerce.stock（physical -= qty, locked -= qty）
→ commerce.stock_log（SHIP）
→ commerce.in_out_order/item（SALE_OUT）
```

测试关注：

- 非待发货状态拒绝；
- `trackingNo` 必填；
- 库存不低于 0；
- 重复发货幂等/拒绝；
- 出库单与流水一致。

## 6. 链路五：售后审核

```text
POST /admin/after-sales/{id}/audit
→ AfterSaleService.audit
→ commerce.after_sale（PENDING_AUDIT）
→ 通过：REFUNDING → COMPLETED（同事务）
→ 驳回：REJECTED（必须填意见）
```

测试关注：

- 非待审核拒绝；
- 驳回无意见拒绝；
- 通过后没有真实退款、不退库存、不减销量；
- 并发审核只成功一次。

## 7. 链路六：C 端 AI 助手

```text
AiAssistant.vue
→ POST /api/customer-service/chat
→ CustomerServiceController.chat
→ CustomerServiceAgentClient.chat
→ agent_service 8088（LangGraph）
→ 商品/知识/订单工具
```

测试关注：

- 未登录问订单返回 `need_auth`；
- 商品推荐是否引用真实 SPU；
- 知识问答是否带引用；
- 超时/降级；
- trace 是否贯通。

## 8. 用调用链设计测试

以发货为例：

| 层 | 测什么 |
|---|---|
| Controller | 参数校验、鉴权、业务码 |
| Service | 状态守卫、事务、幂等 |
| Mapper/SQL | 库存扣减、流水、出库单 |
| 外部 | 物流单号、消息/审计 |
| 页面 | 按钮状态、错误提示、刷新后状态 |

## 练习

1. 打开 `OrderService.ship`，列出所有写操作。
2. 找到 `AfterSaleService.audit` 的事务注解，确认 `REFUNDING` 是否可能被外部读到。
3. 画一条“下单 → 支付 → 发货 → 收货 → 评价”的完整链路。
