# 系统全景：模块、端口、角色与数据域

## 本节目标

- 画出浏览器到数据库的完整拓扑；
- 说出每个 Maven 模块的职责和依赖边界；
- 区分游客、顾客、管理员、AI 助手四类入口。

## 1. 一句话定位

尚品汇是一个**分版本演进的电商全栈演示项目**：

```text
V1.0 后台管理（商品/库存/订单/售后/权限）
  ↓
V2.0 C 端交易（商城 Web + H5）
  ↓
V3.0 智能客服（C 端 AI 助手已接入）
```

## 2. 运行拓扑

```text
Browser
  ├── shang-mall (Vite 5174) ──/api──────┐
  └── shang-admin-web (Vite 5173) ──/admin──┐
                                           ▼
                                  shang-server 8086
                                  ├── identity 上下文
                                  ├── commerce 上下文
                                  └── customerservice 上下文
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              PostgreSQL             Redis              agent_service 8088
              (55434, pgvector)      (56379)            (LangGraph/FastAPI)
```

本地端口约定：

| 服务 | 端口 |
|---|---:|
| 后端 API | 8086 |
| Actuator | 8087（仅回环） |
| 管理端 | 5173 |
| 商城 C 端 | 5174 |
| Agent 服务 | 8088 |
| PostgreSQL | 55434 |
| Redis | 56379 |

## 3. 模块边界

| Maven 模块 | 职责 |
|---|---|
| `shang-common` | Result、异常、JWT、Redis、OSS、审计、过滤器 |
| `shang-identity-api` | 身份对外契约 |
| `shang-identity` | 管理员/顾客认证、RBAC、菜单、部门、字典、文件、日志、配置 |
| `shang-commerce-api` | 交易对外契约 |
| `shang-commerce` | 类目、品牌、SPU/SKU、库存、订单、支付、售后、评价、运营位 |
| `shang-customerservice` | C 端 AI 助手代理 |
| `shang-server` | 聚合启动 + Flyway + 配置 |
| `agent_service` | LangGraph Agent 服务 |

**硬约束**：`shang-identity` 和 `shang-commerce` 的实现模块不能互相直接依赖，跨上下文只走 `*-api`。

为什么用模块化单体而不是微服务：

- 演示项目需要一键启动、事务简单、调试链路短；
- 但模块边界按未来可拆分的方式设计；
- 跨模块只暴露 API 接口，避免“大泥球”。

## 4. 角色与入口

| 角色 | 入口 | 能力 |
|---|---|---|
| 游客 | 商城 C 端 | 浏览首页/分类/搜索/详情；结算需登录 |
| 顾客 | `/login` 手机号+验证码 | 下单、支付、订单、售后、地址、收藏、足迹、评价、AI 助手 |
| 管理员 | 管理端 `/login` | 商品/库存/订单/售后/会员/运营/权限/日志/设置 |
| AI 助手 | 商城右下角浮窗 | 商品推荐、知识问答、订单查询 |

## 5. 数据域

| Schema | 表数 | 核心表 |
|---|---:|---|
| `identity` | 12 | `customer`、`admin_user`、`role`、`permission`、`dept`、`dict`、`system_config`、`operation_log` |
| `commerce` | 24 | `spu`、`sku`、`stock`、`order`、`order_item`、`payment`、`shipment`、`after_sale`、`cart`、`review`、`home_slot` |

完整字段见 `docs/06-baseline/01-数据字典.md`。

## 6. 一次请求怎么走

以商品详情为例：

```text
浏览器 /product/111
→ shang-mall ProductView.vue
→ GET /api/products/111
→ shang-server 8086
→ StorefrontController#productDetail
→ CatalogReadService.detail
→ commerce.spu / sku / stock / review
→ JSON（Long 序列化为字符串）
→ 页面渲染
```

## 常见误区

| 误区 | 事实 |
|---|---|
| “模块化单体就是一个大工程” | 有明确模块边界和 API 契约 |
| “管理端和 C 端共用一个 token” | 两套 token，不通用 |
| “后端 /admin/** 已做接口级 RBAC” | 当前主要认证，细粒度鉴权是演示级 |
| “8086 是网关” | 是聚合启动的 shang-server |
