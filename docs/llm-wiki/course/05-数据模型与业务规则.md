# 数据模型与业务规则：31 张表背后的约束

## 本节目标

- 说出两个 schema 的核心表；
- 背下订单与售后状态机；
- 理解库存不变式和售后/评价的已知缺口；
- 用规则设计测试，而不是只点页面。

## 2. 订单状态机

```text
POST /api/orders
  → PENDING_PAY（锁库存）
PENDING_PAY --支付成功--> PENDING_SHIP
PENDING_PAY --取消/15分钟超时--> CLOSED（解锁）
PENDING_SHIP --后台发货--> PENDING_RECEIVE（扣 physical+locked）
PENDING_RECEIVE --确认收货--> COMPLETED
```

| 转移 | 入口 | 守卫/副作用 |
|---|---|---|
| → `PENDING_PAY` | `POST /api/orders` | 地址/SKU/SPU 校验；`FOR UPDATE` 锁库存；整单事务 |
| → `PENDING_SHIP` | `POST /api/payment/sandbox` | 仅待付款；写 payment、`paid_at`、`sold_count += qty` |
| → `CLOSED` | 取消/超时 | 仅待付款；`locked -= qty`；写 `UNLOCK` |
| → `PENDING_RECEIVE` | `POST /admin/orders/{id}/ship` | 仅待发货；`trackingNo` 必填；扣库存；写出库单 |
| → `COMPLETED` | `POST /api/orders/{id}/confirm` | 仅待收货 |

**没有其他转移**：没有管理端取消、没有自动确认收货、没有支付失败回退。

## 3. 售后状态机

```text
PENDING_AUDIT → REFUNDING → COMPLETED
PENDING_AUDIT → REJECTED
```

关键规则：

- 只有 `PENDING_RECEIVE` / `COMPLETED` 可申请；
- 同订单不能有进行中的售后；
- 仅 `PENDING_AUDIT` 可审核；
- 驳回必须填意见；
- 通过时同一事务写 `REFUNDING` 再写 `COMPLETED`，外部看不到 `REFUNDING`；
- `EXCHANGE` 也走退款流程，不退货入库、不减销量、不写 payment。

测试含义：

- 不要把“退款中”当可观测状态；
- 不要假设换货会换货；
- 必须测退款金额边界和并发重复审核。

## 4. 库存不变式

```text
physical_stock >= locked_stock >= 0
available = physical_stock - locked_stock
```

| 操作 | stock_log.type | 变化 |
|---|---|---|
| 新建 SKU 初始库存 | `INIT` | `+qty` |
| 手工调整 | `ADJUST` | 正入负出 |
| 下单锁库存 | `LOCK` | `+qty` |
| 关单释放 | `UNLOCK` | `-qty` |
| 发货出库 | `SHIP` | `-qty` |
| 采购/盘点 | `PURCHASE_IN` / `STOCKTAKE` | 按单据 |

并发保护不一致：下单/关单用 `SELECT ... FOR UPDATE`；发货/手工调整是普通 select + update，可能静默丢更新。

## 5. 评价与商家回复

- 仅已完成订单可评价；
- 同一订单项只能评价一次；
- 评分 1–5；
- 商家回复只写 `merchant_reply` / `replied_at`，不改星级、内容、可见性；
- 回复 1–500 字，空/超长返回 `40000`；
- C 端只展示 `VISIBLE` 评价的回复。

已知缺口：`rating` 缺失/越界时可能返回 500，而不是 400；订单详情页刷新后不会回显“已评价”。

## 7. 用规则生成用例

以发货为例：

```text
正常：PENDING_SHIP + 合法 trackingNo → PENDING_RECEIVE
状态：PENDING_PAY / PENDING_RECEIVE / CLOSED → 拒绝
参数：trackingNo 为空 / 超长 / 特殊字符
库存：physical、locked 正确扣减，不低于 0
流水：stock_log 写 SHIP；in_out 写 SALE_OUT
并发：两个管理员同时发货，只能成功一次
鉴权：无 token / 会员 token → 拒绝
```
