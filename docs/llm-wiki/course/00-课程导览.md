# 课程导览：如何用 LLM-wiki 学会一个陌生系统

## 1. 这门课解决什么问题

面对一个已经写了多个版本的全栈项目，新人最常见的三个问题是：

1. 需求文档、接口文档、页面、代码、数据库各说各话，不知道信谁；
2. 问 LLM“这个需求要改哪里”，得到的答案像散文，落不到文件和表；
3. 测试只能按页面点，说不出影响面、调用链和风险。

这门课用一套**可追溯的 LLM-wiki**把五层信息连起来：

```text
需求 requirement
  → 页面 page
  → 接口 api
  → 代码 controller / service
  → 数据表 table
```

学完之后，你应该能做到：

- 给定一个需求，10 分钟内列出页面、接口、服务、表、状态机影响；
- 给定一个页面或接口，反查它属于哪条需求、调用哪些服务、落哪些表；
- 给定一个线上问题，用日志、数据库、调用链定位到具体代码；
- 把上述过程讲成面试中的项目亮点，而不是“我测过一些功能”。

## 2. 适用人群

| 角色 | 重点章节 | 收获 |
|---|---|---|
| 测试工程师 | L03-L06、L09-L11 | 影响分析、用例设计、自动化闭环 |
| 后端开发 | L02、L05、L06 | 模块边界、状态机、调用链 |
| 前端开发 | L03、L04、L10 | 页面到接口、ID 精度、契约 |
| 新项目成员 | L00-L04 | 一天内建立系统地图 |
| 面试准备 | L12 + 笔记 | 可复述的项目故事和技术细节 |

## 3. 三条学习路径

### 路径 A：两小时速通（面试前）

```text
L00 → L02 → L03 → L04 → L12
配合：notes/速查表.md、notes/面试题库.md
```

### 路径 B：一天上手（新成员）

```text
L00 → L01 → L02 → L03 → L04 → L05 → L06
下午：打开 graph.html 做两次影响分析
配合：notes/练习题与答案.md 第 1-5 题
```

### 路径 C：一周深入（测试负责人）

```text
每天 2 课：L00-L12
每天 1 个练习：从 notes/练习题与答案.md 选
最后一天：自己写一份新需求影响分析 + 测试方案
```

## 4. 每节课的结构

- **本节目标**：学完能做什么；
- **核心概念**：必须记住的模型或规则；
- **项目实例**：尚品汇里的真实文件、接口、表；
- **常见误区**：新手容易答错的地方；
- **练习**：可以在仓库里直接验证。

## 6. 一句话记住

> Wiki 不是文档，而是**从问题跳到证据的最短路径**。每条结论都要能回到文件、接口或表。
