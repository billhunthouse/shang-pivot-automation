# 商家端发货提示「订单不存在」— 分析、修复与回归

> 日期：2026-11-12  
> 范围：`shang-admin-web` 订单管理  
> 结论：前端把 19 位雪花 ID 转成 `Number` 导致精度丢失，后端按错误 ID 查询返回 404。

## 1. 现象

商家端「订单管理」对订单 `O202611122012190001` 点击「发货」，页面提示「订单不存在」，但该订单在列表中可见、状态为「待发货」。

## 2. 排查过程

### 2.1 后端访问日志

`backend/logs/shang-pivot-access.log`：

```text
GET  /admin/orders/2120852188811464700  status=200  code=40400  msg=订单不存在
POST /admin/orders/2120852188811464700/ship  status=200  code=40400  msg=订单不存在
```

### 2.2 数据库实际数据

```sql
SELECT id, order_no, status FROM commerce."order" WHERE order_no = 'O202611122012190001';
```

```text
id                   order_no              status
2120852188811464706  O202611122012190001  PENDING_SHIP
```

请求里的 `...4700` 与库里的 `...4706` 不一致，且正好是末位差异，符合 JavaScript `Number` 对超过 `2^53-1` 的整数丢失精度的特征。

### 2.3 前端代码定位

`shang-admin-web/src/views/OrdersView.vue`：

```ts
type OrderRow = { id: number /* ... */ }

id: Number(o.id),
```

`2120852188811464706` 超过 `Number.MAX_SAFE_INTEGER`（9007199254740991），`Number()` 后变成 `2120852188811464700`。后续详情、发货接口都用这个被截断的 ID，后端自然查不到订单。

## 3. 修复

### 3.1 订单管理

`shang-admin-web/src/views/OrdersView.vue`：

```ts
type OrderRow = {
  id: string
  // ...
}

id: String(o.id),
```

```ts
async function refreshDetail(rowId: string) {
```

ID 从接口到列表、详情、发货请求全程保持字符串，不再经过 `Number()`。

### 3.2 同类问题加固

排查管理端其他视图后，一并修复了同类转换：

| 文件 | 原写法 | 修复 |
|---|---|---|
| `AftersalesView.vue` | `id: Number(r.id)`、`refreshDetail(rowId: number)`、`loadRelatedItems` 里 `Number(orderId)` | `String(r.id)`、`refreshDetail(rowId: string)`、订单 ID 按字符串校验并传参 |
| `UsersView.vue` | `id: Number(u.id)`、`editingId: number`、`row.id === 1` | `String(u.id)`、`editingId: string`、`row.id === '1'` |

`SettingsView.vue` 的 `id: Number(c.id)` 对应当前 `identity.system_config` 自增小 ID（1–24），暂不涉及雪花 ID；角色 ID 同为种子小 ID。若后续改为雪花 ID，需同步改为字符串。

## 5. 防复发规范

1. 后端所有 `Long` 类型 ID 统一序列化为字符串（Jackson 已配置），前端类型定义必须是 `string`。
2. 禁止对 ID 使用 `Number()`、`parseInt()`、`+id`、`Math.*`；需要比较时统一 `String(a) === String(b)`。
3. 路由参数、`v-for :key`、请求 URL 拼接都直接使用字符串 ID。
4. 新增管理端列表页时，检查 `type XxxRow = { id: ... }` 与 `mapRow` 中的 ID 转换。
5. UI 回归至少断言一次真实请求 URL 含完整 19 位 ID，而不仅是页面提示成功。
