# 评价商家回复 — LLM-wiki 影响分析

> 需求：`docs/01-requirements/PRD-V2.1-评价商家回复.md`  
> 分析日期：2026-11-12  
> 使用知识库：`docs/llm-wiki/`  
> 结论：**低风险增量**；主要影响评价展示与评价管理，不触碰订单/库存/支付主链路。

## 1. 需求映射

| 需求 ID | 既有需求 | 说明 |
|---|---|---|
| FR-REV-REPLY-001 | V2-FR-015、V1-FR-025 | 评价管理增加回复动作 |
| FR-REV-REPLY-002 | V2-FR-015 | C 端商品详情展示回复 |
| FR-REV-REPLY-003 | V1-FR-025、V1-FR-007 | 管理端权限与操作日志 |

## 2. 页面影响

| 页面 | 路由 | 影响 |
|---|---|---|
| 管理端-评价管理 | `/admin/reviews`（`page:admin:/reviews`） | 增加“商家回复”列、回复/修改回复弹窗 |
| 商城-商品详情 | `/product/:spuId`（`page:mall:/product/:spuId`） | 评价卡片增加商家回复块 |

页面-API 依据：

- 评价管理页调用 `GET /admin/reviews`、`PUT /admin/reviews/{id}/status`（`docs/llm-wiki/04-page-map.md`）。
- 商品详情页调用 `GET /api/products/{spuId}`、`GET /api/products/{spuId}/reviews`、加购/收藏等。

## 3. 接口影响

| 接口 | 变更 | 兼容性 |
|---|---|---|
| `PUT /admin/reviews/{id}/reply` | **新增** | 向后兼容 |
| `GET /admin/reviews` | 响应新增 `merchantReply`、`repliedAt` | 前端/客户端忽略未知字段即可 |
| `GET /api/products/{spuId}/reviews` | Review 实体新增字段 | 向后兼容 |
| `GET /api/products/{spuId}` | `reviewsPreview[]` 新增字段 | 向后兼容 |

不受影响：订单、支付、库存、售后、购物车、地址、收藏、AI 助手。

| 层 | 文件 | 变更 |

## 5. 数据与规则影响

- 表：`commerce.review`，只加列，不改既有列/索引/约束。
- 规则：不改变评价状态机（`VISIBLE/HIDDEN`）、星级约束、订单完成才能评价的规则。
- 展示：C 端仍只查 `status=VISIBLE`；隐藏评价的回复不对外展示。
- 审计：新增 `@OpLog(module="review", action="reply")`。

## 6. 测试影响

| 类型 | 影响 |
|---|---|
| 现有契约用例 | `GET /admin/reviews`、`GET /api/products/{spuId}/reviews` 需接受新增字段，不应断言字段集合完全相等 |
| 新增 API 用例 | 回复成功、未登录、空/超长、404、重复回复、隐藏评价不展示 |
| 新增 UI 用例 | 管理端回复 → C 端商品详情展示 |
| 回归 | 评价隐藏/恢复、商品详情加载、评价列表分页、操作日志 |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 回复内容 XSS | P1 | 前端文本插值（不 v-html）；后端长度/空校验 |
| 回复覆盖后无历史 | P2 | 本版本只保留最新回复；历史审计依赖操作日志 |
| 评价隐藏/恢复后回复可见性 | P1 | 复用 C 端 `status=VISIBLE` 查询；用例覆盖 |
| 本地旧数据无列 | P2 | Flyway V22 `ADD COLUMN IF NOT EXISTS`，NULL 正常 |
| 管理端列表列宽/空值 | P3 | 空回复显示 `—`，截断展示 |
| 权限仅认证级 | P2 | 沿用现状并在需求中标注；后续补 RBAC |

## 8. 结论

可以按**低风险增量**开发；不改订单/库存/支付/售后，不需要数据迁移脚本；建议先实现 API 与 DB，再做管理端 UI 和 C 端展示，最后用 API + UI 两条用例闭环验证。
